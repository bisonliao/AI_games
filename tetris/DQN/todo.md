## 问题
项目是用DQN算法训练agent玩俄罗斯方块。我训练了40M步，观察了一下，10M步训练以后，agent只学会了通过左右移动相对充分的利用棋盘空间避免快速死亡，先是堆满中间，然后堆满左边，然后堆满右边，基本上就是三列堆满然后就死了，而没有学会通过旋转+精细化移动来填满空洞并消除行。我怀疑这个学习任务是很艰巨的，且并不能大力出奇迹，还是需要更多的鼓励消除行什么的更精巧的手段。

下面是AI的分析和推荐的做法

我认为你观察到的现象很有代表性：这不是单纯“训练步数不够”，而是当前问题同时存在探索、信用分配和奖励尺度三个困难。



## 为什么 agent 会学会左右堆叠，却不会旋转消行

### 1. 当前动作粒度对 DQN 很困难

现在一个方块的决策被拆成很多 frame：

```text
旋转 -> 左右移动若干次 -> 等待或下落 -> 最终锁定
```

绝大多数动作即时奖励都是 0，真正有意义的奖励要等锁定时才出现。于是 DQN 要解决这样的信用分配问题：

```text
几十个没有奖励的动作
        |
        v
最后一次 hard_drop 产生消行或死亡结果
```

理论上 1-step DQN 可以通过 bootstrap 逐步传播这个奖励，但实际传播很慢，而且还会受到 replay 噪声、目标网络滞后和探索的影响。

左右移动有一个非常直接的生存效果：它可以让当前方块避开高柱，减少马上碰撞。因此 agent 很容易先学到“不要快速死”。旋转则通常需要和后续多次左右移动配合，短期几乎没有可见收益。

### 2. 旋转组合的随机探索概率很低

改造前的 actor 使用固定的分层 epsilon，范围是 `0.05` 到 `0.40`。即使在最高探索 actor 中，随机动作是均匀的，随机旋转的概率也只有：

```text
0.40 / 6 ≈ 6.7%
```

但一个有用的落点通常需要连续做出正确的旋转、移动和落下动作。整段动作序列的概率会快速降低。随机动作能够制造很多死亡样本，却很难偶然制造“正确填洞并消行”的完整轨迹。

### 3. 当前奖励实际上很鼓励“多放几个方块”

目前每放置一个方块有 `+0.10`：

```python
0.10 * piece_placed
```

消一行只有 `+0.75`。这意味着一个消行的即时奖励大约等于 7.5 个普通方块的放置奖励。

这并不表示 `0.75` 数值太小，而是意味着没有消行也能持续获得正奖励。一个能够安全生存几十个方块、最后才死亡的策略，可能在回报上比一个冒险尝试消行但很快死亡的策略更好。

当前奖励优化出来的目标很可能是：

```text
尽量多放方块
避免立刻死亡
不必主动承担旋转和填洞风险
```

这正好对应你观察到的行为。

### 4. 当前势函数的引导力度可能太弱，而且特征不够完整

目前势函数是：

```text
max_height
holes
bumpiness
```

其中 holes 的归一化是 `holes / 200`，权重为 `0.4`。因此新增一个 hole 对势函数的影响只有大约：

```text
0.4 / 200 = 0.002
```

而放置一个方块直接有 `+0.10`。所以形成少量缺口的代价非常小，远小于继续放置方块的收益。

此外，`max_height` 只看最高的一列，无法区分：

```text
所有列都比较平整地堆到 10 层
一列堆到 10 层，其余列很低
```

这两种棋盘的 `max_height` 完全相同，但前者通常更容易继续生存。你看到的“中间、左边、右边依次堆满”可能正是当前特征无法充分区分棋盘质量的结果。

标准 Tetris 启发式通常还会使用：

- aggregate height：所有列高度之和
- holes：洞数量
- bumpiness：相邻列高度差
- wells：竖井深度
- row transitions：行内空满交替次数
- column transitions：列内空满交替次数

其中 aggregate height 往往比 max height 更重要。

## 我建议先区分三个问题

在改奖励之前，最好先确认 agent 是“不会旋转”，还是“会旋转但不会把旋转用对”。

建议观察以下统计：

```text
action/noop
action/left
action/right
action/rotate_cw
action/soft_drop
action/hard_drop
```

以及：

```text
每个 episode 的 lines_cleared
每个 episode 的 survival_pieces
每个方块的平均 action 数
旋转成功率
消行率
死亡时的 max_height、holes、bumpiness
```

这两个现象对应的修复方向不同：

- 如果几乎不使用旋转：主要是探索和动作信用分配问题。
- 如果旋转很多但消行仍接近 0：主要是状态特征、奖励塑形或动作粒度问题。
- 如果偶尔能消行，但随后很快死亡：主要是长期规划和奖励权重问题。

另外建议用一个传统贪心 Tetris heuristic 做环境基准。对每个当前方块枚举旋转和落点，用类似下面的评分：

```text
score =
    line_clear_bonus
  - aggregate_height_penalty
  - holes_penalty
  - bumpiness_penalty
  - wells_penalty
```

如果这个启发式能够稳定消行，说明环境和 SRS 基本没有问题，困难主要在 DQN 学习；如果启发式也很差，则应先排查落点、旋转、消行或顶部隐藏区语义。

## 方案一：最小改动，继续使用当前 frame-level 环境

这是成本最低的路线，但效果可能有限。

### 奖励方面

我不建议直接把四消奖励大幅提升到一个很大的常数。那确实可能导致 agent 为了短期消行制造危险棋盘。

更稳妥的是：

1. 大幅降低 `piece_placed` 奖励，例如从 `0.10` 降到 `0.01` 或接近 0。
2. 保持消行奖励线性，例如 `0.75`、`1.0` 或 `1.5` 逐步实验。
3. 保留终止惩罚，但根据回报尺度重新校准。
4. 将 `max_height` 改成 aggregate height，或者至少同时加入 aggregate height。
5. 提高 holes 的有效惩罚力度，但不要让单个 hole 产生极端惩罚。
6. 可以增加 row transitions、wells 等结构特征，仍然通过势函数差分提供奖励。

核心原则是：

```text
普通放置奖励很小
消行奖励明显
形成洞和高堆有持续的势函数代价
```

势函数差分本身是合理的，因为它不会因左右来回移动而反复刷奖励。问题主要在特征选择和尺度，而不是“必须取消势函数”。

### 信用分配方面

可以考虑 n-step Double DQN，例如 4-step 或 8-step return。

当前 frame-level 环境中，一个消行奖励需要通过许多零奖励动作反向传播。n-step return 能够让锁定奖励更快传到旋转和移动动作。

这比单纯调大 line reward 更可能改善“知道旋转有用，但不知道什么时候旋转”的问题。

### replay 方面

不必马上引入完整的 prioritized replay，可以先使用简单的事件平衡采样：

- 一部分样本来自普通 transition；
- 一部分样本专门来自消行 transition；
- 一部分样本来自终止或高质量落点 transition。

消行样本通常非常稀少，如果完全均匀采样，它们在 256 的 batch 中可能很少出现。事件平衡可以提高正反馈的训练频率。

这会改变采样分布，因此比例应当保守，例如先从 10% 到 25% 开始，而不是让所有 batch 都由消行样本组成。

### 探索方面

原先固定 epsilon 分层策略有一个问题：低 epsilon actor 很快会专注于当前已经学会的“安全策略”，高 epsilon actor 则产生大量随机死亡。

可以考虑：

- 早期 epsilon 较高，随后逐渐衰减；
- 保留多个 actor 的不同 epsilon；
- 延长高探索阶段，直到 replay 中出现一定数量的消行 transition；
- 只有在出现基本消行能力后再降低探索。

如果 replay 中从未出现消行 transition，DQN 不可能从经验中学会消行。这个事实需要重点确认。

## 方案二：仍然使用 DQN，但改成“一个方块一个决策”

这是我认为最有希望的方向。

保留现有 frame-level 环境给：

```text
TetrisEnv.play
图形化调试
键盘操作
低层动作测试
```

另外增加一个用于训练的 placement-level wrapper。训练时，一个 action 直接表示：

```text
当前方块旋转几次
目标横向位置
```

环境内部自动完成：

```text
旋转
横向移动
hard_drop
锁定
消行
生成下一个方块
```

这样每一步都对应一个完整方块的放置：

```text
当前棋盘 + 当前块 + 下一个块
        |
        v
选择一个落点
        |
        v
得到消行、洞、高度和下一个棋盘
```

它的好处是：

- 一个 DQN transition 就对应一个真正的 Tetris 决策；
- 消行奖励立即归属于正确的动作；
- 不再需要通过几十个空动作传播奖励；
- 旋转和横向位置成为同一个组合决策；
- 训练步数从“frame 数”变成“piece 数”，样本效率会高很多；
- 仍然可以使用普通 Dueling Double DQN。

动作空间可以固定为“旋转状态 × 横向落点”，并对不可行落点做 action mask 或明确的非法动作处理。这个设计需要认真定义，但它比在当前 frame-level 环境中硬调奖励更有可能真正学会消行。

如果最终目标是让 agent 学会像人一样逐帧操作，可以先用 placement-level 环境预训练，再在 frame-level 环境中微调。这属于课程学习，仍然没有改变最终任务。

## 方案三：引入启发式经验或课程学习

如果只靠随机探索仍然很难获得第一批消行样本，可以考虑：

- 用传统 Tetris heuristic 生成少量示范 transition；
- 用这些 transition 预热 replay；
- 然后完全切换回 DQN 的 off-policy 学习；
- 或者先在较简单的棋盘、较少方块类型上训练，再逐步恢复完整 7-bag。

这不是必须的，但在稀疏事件极难出现时很实用。它比盲目增加训练时长更可控。

## 我的判断和推荐顺序

我会按下面的顺序推进：

1. 先检查 旧 checkpoint 的 `gradient_updates`，确认实际训练量。
2. 增加低频 action histogram 和消行样本统计，确认 replay 中是否真的出现过消行。
3. 用启发式落点策略验证环境能否稳定消行。
4. 在当前 frame-level 环境上做一组小规模对照：
   - 当前奖励；
   - 降低 `piece_placed`；
   - 增强 aggregate height / holes；
   - 加 4-step 或 8-step return。
5. 如果仍然只有堆叠行为，直接采用 placement-level DQN 训练环境，frame-level 环境继续保留用于交互和最终微调。

最重要的一点是：我不建议现在先简单把消行奖励改成很大。当前现象更像是“动作决策太细、正反馈太稀疏、普通放置奖励太容易获得”的组合问题。奖励调整有帮助，但单独调整奖励可能只是让 agent 更快地学会另一种局部策略。
