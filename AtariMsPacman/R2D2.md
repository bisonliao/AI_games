论文中 R2D2 在 Ms. Pacman 上报告的分数达到数万分，而普通的DQN算法只能达到3000分，不能进入下一个关卡：

- R2D2：42,281.7
- Ape-X：11,255.2
- IMPALA：约 6,501～7,342
- 人类基准：6,951.6

这里的 42,281.7 是 3 个随机种子的最终平均分，评估使用 30 次随机 no-op 开局；每局最多运行 30 分钟，即 108,000 个 Atari frames，报告的是未折扣的 episode return。因此，它不是某一局偶然打出的最高分，也不是只训练几百万帧就能达到的结果。论文明确说明 R2D2 报告最终分数，而 Ape-X 使用的是训练期间最高分。来源：:codex-file-citation{path="C:\\exchange\\papers\\R2D2.pdf" purpose="source"}

R2D2 做了什么

R2D2 可以理解为：

> Ape-X 式分布式优先经验回放 + Recurrent DQN/LSTM + 正确的序列训练方法

它不是简单地把普通 DQN 的全连接层替换成 LSTM。

1. 网络结构

R2D2 使用：

```text
4-frame stack
    ↓
DQN 的三层卷积网络
    ↓
512 单元 LSTM
    ↓
Dueling Q-network
    ├── Value head
    └── Advantage head
```

此外，LSTM 的输入不仅包括图像特征，还包括上一步的：

- reward
- one-hot action

这样 LSTM 可以利用“我刚才做了什么、得到了什么反馈”来建立轨迹状态。

2. 不再存单步 transition，而是存序列

普通 DQN 通常存：

```text
(s_t, a_t, r_t, s_{t+1})
```

R2D2 存的是长度为 80 的连续片段：

```text
(s_t, a_t, r_t),
(s_{t+1}, a_{t+1}, r_{t+1}),
...
(s_{t+79}, a_{t+79}, r_{t+79})
```

相邻序列重叠 40 步，并且不跨越 episode 边界。

这是训练 LSTM 的关键，因为 LSTM 必须看到连续轨迹，而不是随机打乱的单帧。

3. Stored state + burn-in

这是 R2D2 最重要的设计之一。

每条序列在采样时还保存 actor 当时生成的 recurrent hidden state。训练时：

```text
前 40 步：burn-in，只用于恢复 LSTM 状态，不计算 loss
后 40 步：正式训练，计算 TD loss
```

也就是说，长度 80 的序列通常是：

```text
[前缀 40 步 burn-in] [后续 40 步训练]
```

为什么需要这样做？

如果每次从零 hidden state 开始训练，序列开头的 Q 值通常很不准确，BPTT 会把这些错误梯度传播到 LSTM，造成所谓的 destructive updates。R2D2 用两种方式缓解：

- stored state：使用采样时保存的历史 hidden state；
- burn-in：先让当前网络读入一段历史，恢复出较合理的 hidden state，再开始计算 loss。

论文实验显示，两者结合效果最好。对于需要长期行为记忆的任务，这一点尤其重要。即使 Ms. Pacman 看起来基本可观测，LSTM 也能帮助学习更好的时序表示和策略。

4. 5-step Double Q-learning

R2D2 使用 5-step return，并采用 Double DQN 的动作选择方式：

```text
a* = argmax_a Q_online(s_{t+5}, a)
target = r_t
       + γ r_{t+1}
       + ...
       + γ^5 Q_target(s_{t+5}, a*)
```

论文设置：

```text
n = 5
γ = 0.997
target network 每 2500 次 learner update 更新一次
```

相比普通 DQN 常见的 γ=0.99，0.997 更重视较远期的回报。这对 Ms. Pacman 这种“连续吃豆、吃水果、清屏、保命”组成的长期收益可能有帮助。

5. 不裁剪 reward，而是 value rescaling

普通 DQN 常把 reward 裁剪成：

```text
-1, 0, +1
```

R2D2 不直接裁剪 reward，而是使用可逆的 value function rescaling：

```text
h(x) = sign(x) (sqrt(|x| + 1) - 1) + εx
```

其中 ε=0.001。

这样做的目的，是压缩极大的 Q 值范围，同时保留不同奖励大小之间的信息。Ms. Pacman 中吃水果、吃鬼、过关等奖励差异较大，完全 reward clipping 会丢掉这些尺度信息。

6. 序列级 prioritized replay

R2D2 不是只按单个 transition 的 TD error 进行优先级排序，而是给整条序列分配优先级：

```text
p = 0.9 × max(|δ_i|)
  + 0.1 × mean(|δ_i|)
```

长序列中如果只使用 mean TD error，大错误可能被平均掉。因此 R2D2 强调 max TD error，让包含关键事件的片段更容易被重新训练。

另外使用：

```text
priority exponent = 0.9
importance-sampling exponent = 0.6
```

7. 分布式 actor-learner

R2D2 训练时大约使用：

```text
256 个并行 actor
1 个 GPU learner
batch size = 64
每批是 64 条长度 80 的序列
```

actor 负责持续产生经验，learner 从共享 prioritized replay 中采样训练。论文训练规模达到数十亿甚至 100 亿级别的 environment frames。

这点非常重要：R2D2 的 42k 分数不能和“单个环境、训练几千万帧的普通 DQN”直接比较。它既有算法改进，也有更大的数据吞吐和训练规模。

为什么你的普通 DQN 只有约 3000 分

这其实并不意外。普通 DQN 和论文中的 R2D2 存在多个差异：

| 方面 | 普通 DQN | R2D2 |
|---|---|---|
| 经验单位 | 单步 transition | 长序列 |
| 网络 | CNN | CNN + 512 LSTM |
| replay | transition prioritized 或 uniform | sequence prioritized |
| recurrent state | 无 | stored state + burn-in |
| return | 常见 1-step | 5-step Double Q |
| 折扣率 | 常见 0.99 | 0.997 |
| reward | 通常 clipping | value rescaling |
| 数据采集 | 单 actor | 约 256 actors |
| 训练规模 | 通常较小 | 数十亿/百亿 frames |
| 策略表示 | 主要依赖当前帧 | 使用完整行为历史 |

因此，3,000 分并不表示实现失败；它大约已经接近普通 DQN 在这个游戏上的典型水平。42,000 分更像是一个完整的大规模 R2D2 系统的结果，而不是单个局部技巧带来的提升。

对 Ms. Pacman，最值得优先尝试的改进

如果你目前只有一个普通 DQN 环境，不建议一开始就复制 256 个 actor。比较实际的升级顺序是：

1. 先加入 Double DQN、Dueling network 和 n-step return。

2. 从单步 replay 改成序列 replay，例如：

```text
sequence length = 80
burn-in length = 40
training length = 40
```

3. 使用 CNN + LSTM，并保存每条序列起始时的 hidden state。

4. 使用 5-step target，尝试：

```text
gamma = 0.997
```

5. 保留原始 reward，加入 value rescaling；同时做 reward clipping 对照实验。

6. 对序列而不是单步 transition 做 prioritized replay，优先级使用 max TD error 与 mean TD error 的混合。

7. 增大训练数据量和 actor 数量。即使只能做到 8～32 个 actor，也通常比单 actor 更接近 R2D2 的训练条件。

8. 确认评估设置一致：30 个随机 no-op 开局、多局平均、不要只看训练过程中的偶然最高分。

一个简化版的训练目标可以写成：

```text
h_t = LSTM(obs_t, action_{t-1}, reward_{t-1}, h_{t-1})

a* = argmax_a Q_online(s_{t+5}, a)

y_t = h(
      r_t + γr_{t+1} + ... + γ^4r_{t+4}
      + γ^5 h^{-1}(Q_target(s_{t+5}, a*))
      )

loss = Huber(Q_online(s_t, a_t) - y_t)
```

其中 loss 只在 burn-in 后的时间步上计算。

最关键的结论是：对你这个问题，优先级最高的不是把普通 DQN 的 CNN 再加深，而是改成“连续序列 replay + LSTM + burn-in + stored recurrent state”。论文的消融实验显示，去掉 LSTM 后 Ms. Pacman 曲线明显变差；论文作者还指出，LSTM 在 Atari 中不仅提供记忆，也改善了表示学习。
